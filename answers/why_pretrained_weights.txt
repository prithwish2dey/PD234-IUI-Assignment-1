Why I used a pre-trained model

Training YOLOv8 from scratch means every weight starts random, so the
network has to learn what edges, textures, and objects even look like
before it can detect anything. That normally takes hundreds of epochs
on a huge dataset like full COCO (about 118,000 images). I only had
COCO128, just 128 images, so training from scratch left the model
barely better than guessing - mAP stayed near zero even after 60
epochs.

Switching to COCO-pretrained YOLOv8n weights fixed this. The backbone
already knew how to recognise common objects, so fine-tuning only had
to adjust it slightly and teach the new DINOv2 fusion layer how to add
extra context. The improvement was large: after 40 epochs of
fine-tuning, overall mAP@0.5 reached 0.58 and mAP@0.5:0.95 reached
0.42, with several classes (airplane, train, zebra, horse) scoring
close to 0.99 mAP@0.5. The from-scratch run never got anywhere near
that even after 60 epochs.

Main benefits:
- Much faster convergence, since the model isn't learning from zero.
- Usable accuracy from very little data, which matters a lot with only
  128 training images.
- Less overfitting, especially after freezing the backbone, since
  fewer weights are being updated on such a small dataset.
- Training effort goes into what's actually new (the DINOv2 fusion
  branch) instead of being wasted relearning basic object recognition.

In short, pre-trained weights turned an unrealistic task - learn 80
object classes from 128 images - into a realistic one - adapt a model
that already knows those classes to a new fusion technique using those
same 128 images.
