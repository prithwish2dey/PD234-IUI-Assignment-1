Why pre-trained weights help - a compact mathematical view
============================================================

Let L(theta) be the detection loss (box + class + DFL loss) as a
function of the network parameters theta, and let theta* be a set of
parameters that generalises well on object detection in general (not
just on my 128 images).

Training from scratch:
    theta_0 ~ random init  ->  theta_0 is far from theta*
    Gradient descent needs T_scratch steps to get close to theta*:
        ||theta_0 - theta*||  is large
        T_scratch ~ O( ||theta_0 - theta*|| / (eta * |grad| ) )  -> large

Training from pre-trained COCO weights:
    theta_coco = argmin L_coco(theta), trained on ~118,000 images
    ||theta_coco - theta*|| << ||theta_0 - theta*||
    because theta_coco already sits in a good region of the loss
    surface for "general object detection", not far from the region
    that also solves my smaller problem.
    So the number of fine-tuning steps needed:
        T_finetune ~ O( ||theta_coco - theta*|| / (eta * |grad|) )  -> small
    => T_finetune << T_scratch

This is exactly what I saw experimentally: mAP that stayed ~0 after
60 epochs from scratch reached mAP@0.5 = 0.58 (overall) after 40
epochs of fine-tuning, with individual classes like zebra and airplane
reaching ~0.99 mAP@0.5.

Sample complexity argument:
    For a model with roughly N trainable parameters, standard learning
    theory says the number of samples needed to generalise scales
    roughly as:
        n_samples ~ O(N / epsilon)
    for a target generalisation error epsilon.

    - From scratch: effectively all N parameters are "free", so the
      required n_samples is large (COCO itself: ~118,000 images).
    - COCO128 gives n_samples = 128, which is far below that
      requirement -> from-scratch training is in the
      under-determined regime: too many parameters, too little data,
      so the model overfits/doesn't converge meaningfully.

    - Fine-tuning with the backbone frozen reduces the effective
      number of free parameters from N to N_head << N (only the
      neck/head and the new DINOv2 fusion layers are trainable).
      That shrinks the required sample count proportionally:
        n_samples_finetune ~ O(N_head / epsilon) << O(N / epsilon)
      which 128 images can actually satisfy.

Bias-variance framing:
    theta_coco acts as a strong prior / informative starting point.
    It injects a low-variance, low-bias initial estimate of "what
    objects look like" into the optimisation, so the optimizer only
    has to search a small neighbourhood of parameter space instead of
    the entire space. This directly reduces variance (less overfitting
    to the 128 training images) without increasing bias, since
    theta_coco already encodes real object-detection structure rather
    than an arbitrary constraint.

Summary in one line:
    Fine-tuning = short optimisation path (theta_coco -> theta*) +
    fewer free parameters (N_head << N) + prior knowledge acting as a
    regulariser -> faster convergence, lower sample requirement, less
    overfitting, all compared to training from a random theta_0 with
    all N parameters free and only 128 images to learn from.
